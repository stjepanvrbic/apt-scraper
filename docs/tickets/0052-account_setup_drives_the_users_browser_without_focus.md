## Outcome

The Google and Telegram parts of the account setup run in the user's own browser, with their logins, through Hermes's browser tools, while the user keeps chatting in the dashboard and keeps using the mouse. Nothing in the setup depends on a window being in the foreground, and the setup continues from what is saved after a reinstall.

## Acceptance

- [x] Observed on the owner's first setup (Windows, Brave as default browser): the `account-connections` skill drove the Google Cloud console with `computer_use` in the user's browser. Typing from the background was blocked, typing in the foreground minimized the window, and the agent gave up and handed the user a click-by-click list. After the fix the skill never uses `computer_use` for a web page.
- [x] The profile turns on Hermes's real-profile browsing and headed mode (`browser.use_real_profile`, `browser.headed`): Hermes snapshots the default browser's active profile (Chrome, Edge, Brave, Chromium) into its own copy, launches the real browser binary on it in a visible window, and the agent acts in that window with `browser_navigate`, `browser_click`, `browser_type`, `browser_snapshot` and the rest. The user sees every page and does the sign-in and consent clicks there. Set the keys in `profile/config.yaml` and, because a reinstall keeps the user's `config.yaml`, also from both installers when unset, as `delegation.model` is set.
- [x] The Google section (project, APIs, consent screen, publish, client, download, authorization) and the Telegram section (BotFather, userinfobot, the bot's chat, through https://web.telegram.org) are rewritten for the browser tools. The one-time authorization address is read with `browser_snapshot` or the tab list, not from a screenshot. The bot token is never captured: the skill keeps its rule about screenshots and snapshots of the BotFather chat.
- [x] Windows: a running browser locks its cookie database, so the first snapshot needs the browser fully quit. Hermes then falls back to a fresh browser and reports `real_profile_unavailable`. The skill handles both without stopping: it tells the user the window is signed out and asks them to sign in there, or offers to close their browser and reopen the dashboard afterwards with `browser.real_profile_autoclose`. The user is never sent to a terminal or asked to type a password in the chat.
- [x] `computer_use` remains only for what no browser can do: macOS permission dialogs, privacy settings and a terminal program. The skill says so, and the Windows setup needs none of them.
- [x] After `hermes profile install --force` through the installer, the saved interview and the connection results are still there and the next conversation continues the setup from them: `settings.py status` and `connections.py status` read what the previous install saved. Verify on a throwaway profile, and make the installer or the skill resume rather than restart.
- [x] A Google Cloud project `apt-scraper` that the earlier attempt may have created is reused, not duplicated: the project step checks the picker first.
- [x] Tests cover the skill's rules (no `computer_use` on web pages, the browser keys set by both installers) with the existing test style; no test drives a real Google or Telegram page, opens the owner's browser, or snapshots the owner's browser profile.

## Spec

docs/spec.md, Installation and setup: the setup is guided by the agent in the dashboard chat; the user does only what needs their own hands. Add that the agent works in the user's browser through Hermes's browser tools, in a window it opens with the user's logins, and that nothing in the setup needs the user to keep a window in front.

## Design

Hermes 0.22.5 offers three lanes beside computer use: its headless Chromium (no logins), `browser.cdp_url` or `/browser connect` to a browser started with a debugging port (needs a non-default user-data dir, so no logins either), and `browser.use_real_profile`, which copies the user's active profile, launches the user's own browser binary on the copy and drives it through agent-browser. The real-profile lane is the one that carries the user's Google and Telegram logins, works with Brave, Chrome and Edge, and keeps the user's live browser and the dashboard chat untouched. Read `website/docs/user-guide/features/browser.md` in the installed Hermes (`%LOCALAPPDATA%\hermes\hermes-agent`) for its contract, including the Windows first-snapshot lock, `real_profile_autoclose`, `hermes browser close-profile` and the `real_profile_unavailable` result. Hermes's browser extension protocol has no shipped extension, so it is not an option.

The interview state lives in the listing store outside the profile and the connection results in `$HERMES_HOME/apt-scraper/connections.json`, which a distribution reinstall leaves alone; resuming is the first-message `status` calls in SOUL.md.

Verification must not touch the owner's browser, browser profile or Hermes profile: no real-profile snapshot on this machine, no Google or Telegram page, no `computer_use`. Hermes experiments run on a throwaway `HERMES_HOME` under `%TEMP%` with the headless Chromium or stubs.

## Deviations

- The profile also sets `browser.backend: "off"`. In Hermes 0.22.5 an unset backend gives the agent only `browser_exec`, which writes Python against the page, instead of `browser_navigate` and the rest. Checked on a throwaway `HERMES_HOME`: the `hermes-cli` and `hermes-api-server` toolsets get `browser_exec` alone without it, and `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`, `browser_press`, `browser_scroll`, `browser_back`, `browser_console`, `browser_get_images` and `browser_vision` with it.
- The profile also sets `browser.real_profile_autoclose: true`, so Hermes's own locked-profile message offers to close the browser, as the skill does.
- "When unset" is read as "`config get` prints Hermes's default": `config get` fills in the defaults, so it prints `false` and an empty backend for keys config.yaml leaves out. A config that sets `use_real_profile`, `headed` or `real_profile_autoclose` to `false` explicitly looks the same and gains `true`. A backend the user chose, such as `browser-use`, is kept.
- `browser.inactivity_timeout` stays at Hermes's default. The gateway reads it once at start, from the root profile's config, so the profile cannot raise it. A Hermes-launched real-profile browser survives the idle cleanup (Hermes terminates it only when the gateway exits), but a fresh browser from the `real_profile_unavailable` fallback closes about two minutes after the agent's last browser action. The skill therefore waits for the user's sign-in and consent by taking a `browser_snapshot` about every 30 seconds, with `sleep 30` between them, for up to 10 minutes, which also spares the user a "done" in the chat.
- Hermes 0.22.5 has no tab-list tool with the built-in browser tools (`browser_cdp` appears only with `/browser connect` or `browser.cdp_url`). The authorization address comes from `browser_snapshot` with `full` true: Chrome's error page for `http://localhost:1/?...` names the full address after "The webpage at". Checked in Hermes's headless Chromium on a throwaway `HERMES_HOME` with a local stand-in for the consent page: the plain snapshot shows only the heading, `location.href` is `chrome-error://chromewebdata/`, and the full snapshot carries the address with its `code` unredacted.
- On Windows the skill decides about closing the browser before its first browser action in a conversation, from whether `$HERMES_HOME/browser-profile/*/.hermes-snapshot-complete` exists. Hermes keeps one browser session per conversation, so after a fallback to a fresh browser, closing the user's browser would not switch that conversation to their logins. If `hermes -p apt-scraper browser close-profile` fails, the user signs in in the agent's window.
- Telegram runs in Telegram Web (`https://web.telegram.org/k/#@<username>`), not `t.me` links, which hand off to the desktop app. After the user has copied the token, the agent sends `/help` to BotFather through the message field's ref before it opens another page, so that the chat list's preview of BotFather's last message, which the next snapshot reads, is not the token. While BotFather may show the token, the agent asks in the chat and ends its turn instead of waiting with snapshots.
- The dashboard's Channels page opens in the agent's window too; the user pastes the token into the form there.
- When the client download does not arrive, the agent writes the client file from the creation dialog (client ID and secret, which Google does not treat as a secret for a desktop client). Checked on the throwaway profile: the google-workspace `setup.py` stores such a file and builds an authorization URL from it.
- Resuming needed no installer change. A reinstall keeps `connections.json`, the listing store, `.env`, `google_client_secret.json` and `browser-profile/`; the skill now skips what an earlier attempt finished: a stored client goes straight to authorization, an `apt-scraper` project in the resource list is reused, enabled APIs, an existing consent screen, a published app and an earlier client download are skipped.
- The contact skill said its browser tools run Hermes's own browser. They now run on the copy of the user's profile too, so a contact form may arrive filled in from the user's account; the skill now treats such fields as personal information and empties those not approved.
- README's "Connect your accounts" describes the browser window, the Windows close offer and, for macOS, computer use for the Homebrew terminal.

## Result

- `profile/config.yaml` sets `browser.backend: "off"`, `use_real_profile`, `headed` and `real_profile_autoclose`. Both installers have a step "Browser for the account setup" that sets each of them with `hermes -p apt-scraper config set` while `config get` prints Hermes's default, after the profile install that keeps the user's `config.yaml`.
- The `account-connections` skill (1.4.0) has a section "The browser": every web page through the browser tools in the visible real-profile window, `computer_use` only for macOS permission dialogs, macOS privacy settings and a terminal program, waiting by snapshots while the user acts, `used_real_profile` and `real_profile_unavailable`, and the Windows first-copy choice between `hermes browser close-profile` and signing in in the window. The Google and Telegram sections are rewritten for it, with the resume skips above.
- `docs/spec.md` › Installation and setup says the setup is guided in the dashboard chat, that the agent works in the user's browser through Hermes's browser tools in a window it opens with their logins, that nothing needs a window in front, and that a reinstall continues from the saved state.
- Tests: `BrowserStepTests` in `tests/test_installers.py` runs each installer's browser step against a fake `hermes` that answers `config get` with Hermes's defaults and records `config set` (unset config, already set, a user's own backend), and checks the distribution config. `SkillTest` in `tests/test_connections.py` checks that the Google and Telegram sections use `browser_navigate` and name no computer use, `start`/`open`, address bar or `t.me` link, that computer use appears only for a terminal, and that the BotFather no-capture rule is there. Both fail against the previous installers and skill. `python -m pytest tests -q` from Git Bash: 619 passed. `ruff check .` clean.
- Reinstall, verified on a throwaway `HERMES_HOME` under `%TEMP%` with Hermes 0.22.5: profile created, distribution installed, part of the interview saved, `connections.py check gmail calendar` run, a client file stored, `TELEGRAM_ALLOWED_USERS` set and a real-profile copy marker created; then the installer's profile step (keep config, `hermes profile install --force --yes`, restore) and its browser step. Every file outside `skills/` and `cron/` was unchanged except `config.yaml`, which gained the browser keys, `distribution.yaml` (install time) and Hermes's config backups; `settings.py status` and `connections.py status` printed the same before and after.
- Not verified: nothing ran against Google, Telegram, the owner's browser or a real-profile copy on this machine, and no headed window was opened. Untested live: Brave's real-profile copy and launch on Windows, `close-profile` against a running Brave, Google sign-in inside a browser that Hermes drives over CDP, the Telegram Web flow, the dashboard's Channels form in the agent's window, a download's location in the copy window, and macOS.
